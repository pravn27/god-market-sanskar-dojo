# Documentation map

This documentation is the source of truth for the local-only God Market Sanskar Dojo.

| Area | Purpose |
| --- | --- |
| `product/` | User problem, scope, workflows, feature catalogue, and delivery roadmap |
| `architecture/` | System boundaries, components, data model, and decisions |
| `specifications/` | Testable behaviour for rituals, gates, grading, virtues, and improvement |
| `validation/` | Test strategy, acceptance criteria, and verification evidence |
| `operations/` | Local installation, privacy, and recovery |
| `knowledge-base/` | Stable ASTA definitions and the Code of Conduct used by the specifications |

Start major features from the [product delivery roadmap](product/delivery-roadmap.md). Every scoring rule must trace back to the [ASTA rules catalogue](specifications/asta-rules-catalogue.md).

## Documentation rule

No feature moves to implementation until its specification has a defined purpose, inputs, rules, failure behaviour, acceptance criteria, and validation scenarios.

## Core principle

Points come only from following the ASTA process. Profit and loss are displayed but never earn points, never raise a level, and never count as improvement.
